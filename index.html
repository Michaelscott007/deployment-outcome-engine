HOW I BUILD

Own the outcome, not the ticket.

The pattern is deliberately boring in the places where boring creates reliability.

01

Frame

Clarify the business outcome, inputs, constraints, side effects and definition of done.

02

Instrument

Define traces and evals before polishing prompts. If failure is invisible, iteration is theatre.

03

Build

Use the simplest architecture that can complete the loop. Add agentic complexity only when the task benefits from it.

04

Break

Attack the system with missing context, conflicting instructions, malformed inputs and tool failures.

05

Ship

Put it behind the right approval boundary, monitor production behaviour and turn repeated fixes into system improvements.
